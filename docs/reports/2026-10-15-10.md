## Summary

The site and database had been moved to a separate data disk (11:18), then switched to a second one (11:41). Both data disks were then deleted, and the VM restarted with only a blank disk attached. The site was down from about 11:45 to 12:01. **Almost nothing is lost for good.** The live copy is now the system disk. The database is restored from a complete dump taken at 11:40:53. The code is rebuilt from Claude's session log and Liam's theme zip. Everything is committed, and config matches the database.

## What was done

**Cause:**
- **Three disks with nearly the same names:** `ishop2much-data` (100 GB, the first data disk), `ishopway2much-data` (10 GB, live from 11:41) and `ishopway2muchdata` (the new blank disk).
- **Wrong disk removed:** the step "detach and delete the 100 GB disk, then restart" removed the live 10 GB disk instead. After that, both data disks were deleted.
- **No safety net for the data disks:**
  - No snapshot had been taken of either one, and the snapshot schedule wasn't attached to them.
  - Claude's instructions for deleting a disk didn't ask for a snapshot first.
  - All backups were on the same VM.
- **Unnecessary risk:** the data disk itself added risk for little benefit. The whole site is about 600 MB.

**Downtime:**
- About 11:45 to 12:01: the services correctly refused to start on empty folders.
- About 12:11: under a minute in maintenance mode for the database restore.

**Restore steps:**
- **12:01:** brought the 11:17 copies back to the system disk. A tarball of them is in /var/backups/ishop-recovery. The three data-disk lines in /etc/fstab are commented out.
- **12:06 to 12:10, code rebuilt** from Liam's zip and the session log. Each change was replayed word for word onto the same starting commit:

## What's next

**Prevention, proposed for Liam's approval:**
1. **No separate data disk for now.**
   - Remove the commented-out data-disk lines from /etc/fstab, the RequiresMountsFor drop-ins and scripts/move-to-data-disk.sh.
   - Delete the leftover copies (/var/www/ishop.pre-move and similar) once this is approved.
   - Liam can delete the blank 10 GB disk `ishopway2muchdata`.
2. **Nightly backups copied off the VM** to a private Cloud Storage bucket after each 02:15 run, with a 30-day lifecycle.
   - The VM's account can't write to storage today. This needs a bucket, plus either a storage scope change (the VM must be stopped for about 2 minutes) or a dedicated service account.
   - Claude will write the steps.
3. **Git pushed to a private remote** (for example a private GitHub repo with a deploy key) at the end of every session.
   - Secrets are already excluded from git.
4. **Liam's daily snapshot schedule attached to the boot disk** `ishopwaytoomuch`, which now holds everything.
5. **New rule for Claude:** any instruction that detaches or deletes a disk starts with a snapshot step, and names the disk by name, size and **In use by**.
